# Vendoring License Decision

> **Decision date:** 2026-05-09
> **Decided by:** axiom-design-pairing feature workflow, T0 (license verification)
> **Outcome:** APPROVED — `skill-creator` may be vendored.

## Investigation

### Repo-level license

`anthropics/skills` (https://github.com/anthropics/skills) has no root-level `LICENSE` file; GitHub API returns `"license": null`. The README clarifies that licensing is per-skill: "Many skills in this repo are open source (Apache 2.0). [...] [docx/pdf/pptx/xlsx] are source-available, not open source."

### Per-skill license

`skills/skill-creator/` contains its own `LICENSE.txt`. Confirmed via:

```bash
gh api repos/anthropics/skills/contents/skills/skill-creator/LICENSE.txt
```

License: **Apache License 2.0** (January 2004).

## Apache 2.0 obligations for vendoring

Per the Apache License 2.0 terms:

1. **Include LICENSE** — copy `LICENSE.txt` from upstream into `skills/_vendor/skill-creator/LICENSE`.
2. **Include NOTICE if present** — fetch and include any `NOTICE` file from upstream skill-creator (verify presence at vendor time).
3. **State changes** — record modifications in `UPSTREAM.md`. The principal change is frontmatter rewrite: `name: skill-creator` → `name: _vendor:skill-creator` (to prevent trigger collision).
4. **Preserve copyright notices** — do not strip any `Copyright` lines in vendored content.
